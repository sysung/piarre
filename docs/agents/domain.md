# Domain docs

Read [OpenSpec main specs](../../openspec/specs/) for adopted requirements. Read the relevant OpenSpec change's `design.md` for design decisions and rationale. Treat active change designs as proposals and check archived decisions against the current specs and any later changes that supersede them.

When a skill refers to ADRs or `docs/adr/`, use the relevant OpenSpec change design as Piarre's decision record. Record architectural decisions there. Link to the specific section from issues and other docs. Follow the [documentation authority decision](../../openspec/changes/archive/2026-11-13-055759-consolidate-project-documentation/design.md#d3-make-openspec-authoritative-and-preserve-discovery-freedom) when sources conflict.

Use the root `GLOSSARY.md`, when present, for shared Piarre terminology. Link definitions to their OpenSpec sources.
