# Source-linked arithmetic development experiment

Architect and Arena compared source-anchored expression trees with a generative final answer against backward-only operation tables with deterministic numeric rendering. Parent rubric scores tied at9/10; the independent cross-judge scored both8/10 and selected the table design because a final generative step could reverse a correct calculation.

Use the table base. Graft generic numeric comparisons and code-derived citation unions from the expression-tree alternative. Reject task-specific capacity, eligibility and permission templates. Exact quotes and bounded numeric tokens replace model-generated character offsets, whose counting adds an unrelated failure mode. Units remain model interpretations, not a new conversion registry or a dimensional-validity claim.

The caller supplies a question and original status-bearing sources. `assess(rawPlan, inquiry)` returns a dialogue proposal, a deterministically rendered numeric proposal with source quotations, or a rejection. Quantities contain a source ID, an unchanged quotation and a numeric token. Code derives numeric values. Operations refer only to quantities or earlier operation rows. Outputs are values or generic comparisons. Source qualifications are verbatim quotes. No generated code, functions, shell or arbitrary expression evaluation is supported.

Candidate call1 proposes dialogue or a calculation table. After bounded parsing and arithmetic, call2 audits meaning, completeness, qualifiers and authority against all original evidence. It accepts or rejects; it cannot repair. Numeric rendering never grants permission. Dialogue is also audited. The same small model's audit is not independent semantic verification. Incorrect operands, units, labels or omissions can still survive. Those are failures in external evaluation.

The direct control drafts then refines from the same original sources. Both arms have at most2 calls,1024 output tokens,6000 UTF-8 bytes per complete prompt,60-second deadlines and the same pinned local model/temperature/thinking settings. An invalid plan is a failed sample, not a successful abstention or opportunity for a repair call.

Offline adversarial arithmetic tests precede inference. The first development screen has one arithmetic question with a nonnumeric authorization prerequisite and one missing-fact question. Maximum8 calls total. It can reject or justify another development step, never establish superiority. Freeze the implementation and prompts before independent fresh validation. If numeric output drops prerequisites or ordinary completion, scrap or narrow it.

Grounding was skipped because this is a greenfield research module. Sketch and cross-judge are complete. Human checkpoint was not requested. Implementation follows this smaller synthesis; source meaning and authority stay explicitly unverified.

After two failed development screens, scrap the combined first-call dialogue/calculation interface. The first call now has no final-answer branch. It emits a numeric table or a no-calculation marker. Only the second call answers ordinary questions, using the original direct-answer instruction. A numeric table is evaluated and audited as before. This keeps the table interpreter and exact source validation while reducing the first model's competing tasks. It does not establish that extraction or final task completion works.
