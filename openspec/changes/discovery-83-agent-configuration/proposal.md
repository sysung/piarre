# Proposal

## Why

Users need to understand effective agent instructions, copies and scope before adopting another configuration system. Test a small import-and-inspection journey instead of committing to a production agent library.

## What Changes

- Prepare a disposable roster and inspector, with a small canvas alternative over identical data. Support one sanitized repository-local SKILL.md bundle copied into experiment-owned state; preserve unsupported fields and original source bytes.
- Prepare the source-linked cases and failure controls in [verification.md](verification.md), reusing existing implementation and experiment owners.
- Publish this plan for human review. All Apply/TDD, model/human trials and archive work remain pending.

## Capabilities

### New Capabilities

- `agent-equipment-preview`: Observable, version-bound experiment behavior for this discovery, without production adoption.

### Modified Capabilities

None. No main capability exists in the current OpenSpec inventory.

## Impact

#87 consumes version/dependency terminology without depending on a production template store. #102 owns later instruction-volume experiments. Map the lifecycle owners explicitly: grilling explores consequential gaps, OpenSpec records proposed scope/tasks, TDD builds approved work, pstack primarily verifies intended behavior and supported evidence, and archive records the completed reviewed change. Do not automatically retire or install any skill.

The proposed implementation targets are listed in [design.md](design.md). This PR changes only OpenSpec planning files and shared configuration. It does not implement the experiment, change runtime authority or complete [issue #83](https://github.com/sysung/piarre/issues/83).
