With the fix, the same control invokes an acceptance-only prompt. The detail body also states that the changes are already integrated and acceptance does not reapply source files. Its confirmation creates one acceptance event and no new publication, checkpoint, or journal. Cancellation changes nothing. Parallel confirmations across two SQLite connections produce one source publication, one source checkpoint, and one acceptance event. Fresh publication still requires its separate apply-and-accept prompt.
- **V07 replay.** Exact retry originally failed after freshness invalidation cleared projected acceptance. The fix identifies the prior acceptance through existing events and the recorded integration operation. The current projection stays stale and unreviewed, so retry does not imply verification of the later contents.

The other proves a peer cannot replay while a real source recovery publication remains pending. The migrated suites passed before deleting the old methods. ## Shape and cleanup decisions

The host-only discriminated binding carries plan and result identity, source and candidate manifests, criterion-bound checks, and the publication operation. The publish operation ID is allocated during review so exact retries retain its identity. This adjusts the D3 sketch without a host cache or WeakMap. The Webview cannot choose or receive the binding. Existing lifetime guards remain in place. Stage 4 owns document and selection guards.

No further publication helper was added. The existing private `beginPublication` and `endPublication` already hold the common bookkeeping. Removing the unused restore path removes one duplicated publication block. Remaining reconciliation and recovery paths have distinct foreign-owner cleanup and uncertainty handling that a shared callback would obscure.
