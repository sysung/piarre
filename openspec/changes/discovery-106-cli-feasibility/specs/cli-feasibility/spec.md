# Spec Delta

## Purpose

Evaluate whether a small editor-independent handoff workflow earns further development while preserving the validation-first pilot, accepted intent, and explicit human sequencing authority.

## ADDED Requirements

### Requirement: Distinguish audit from implementation
The feasibility report SHALL map source-pinned reusable domain behavior and app-hosted storage, retrieval, provider, execution, recovery, and native services. It SHALL identify minimal extraction candidates and blockers without claiming extraction or CLI capability already exists.

#### Scenario: A reusable domain function requires host state
- **WHEN** an inspected journey reaches storage or transport hosted by the editor app
- **THEN** the report names the host dependency and marks any proposed shared interface as unimplemented

### Requirement: Require pilot and sequencing evidence
Before any executable CLI prototype, the work SHALL record #100/#91 pilot evidence and an explicit human sequencing decision choosing bounded CLI, smaller helper, existing approach, or defer. Plan approval and source-audit completion SHALL not substitute for that decision.

#### Scenario: The architecture audit passes before the pilot
- **WHEN** the audit finds a plausible thin adapter but the pilot or sequencing decision is missing
- **THEN** executable CLI work remains gated and no runtime package or command is built

### Requirement: Compare the smallest matched journey
The protocol SHALL compare one repository-to-inspectable-handoff-to-resumption journey against versioned Markdown and the same existing agent with matched source, accepted intent, settings, and budgets. It SHALL test whether the existing export plus a small helper is sufficient and preserve an identical-handoff direct-agent control.

#### Scenario: Better handoff text improves both arms
- **WHEN** the same handoff supplied directly to the existing agent gives the same benefit
- **THEN** the report does not attribute that benefit to CLI packaging

### Requirement: Preserve review and authority boundaries
Any later handoff slice SHALL distinguish accepted and pending intent, preserve project/source identity and consequential unknowns, reject missing or changed accepted snapshots, and avoid implicit execution/provider events. Clarification skip SHALL retain provisional assumptions without skipping authorization.

#### Scenario: Accepted snapshot bytes are missing
- **WHEN** the referenced accepted snapshot is missing or modified
- **THEN** handoff generation fails visibly rather than substituting newer working text

### Requirement: Verify operational instructions before human trials
Any later executable slice SHALL have independently verified launch, stop, reset, interruption/recovery, and inspection instructions on an available isolated host before requesting human participation. Missing prerequisites SHALL remain blockers without implicit installation or download.

#### Scenario: Only an unverified launcher exists
- **WHEN** a launcher is on PATH but pinned-host availability and no-download behavior are unverified
- **THEN** the protocol remains not ready for human testing

### Requirement: Retain comparative and incomplete evidence
The report SHALL track actual effort, explanation/review burden, fatigue, voluntary reuse, setup friction, latency, correctness, and all-attempt total cost. Unperformed trials SHALL remain pending. Proceed, narrow, retain, and defer SHALL be valid outcomes without implying VS Code deprecation or model adoption.

#### Scenario: No human trial has occurred
- **WHEN** source mapping and deterministic checks are complete but comparative human evidence is absent
- **THEN** the report records the evidence gap and makes no reduced-fatigue or usability claim
